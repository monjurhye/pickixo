Pickixo — credentials that must live in a password manager, NOT in this backup
================================================================================

These three items exist to get INTO the backup system itself. Putting any of
them inside the backup they unlock would be circular: lose them, and every
nightly archive in Drive becomes permanently unusable even though every byte
of it is still sitting there, intact.

This file is a reminder of WHAT to store. It does not contain the actual
values — those belong in a password manager (Bitwarden, 1Password, etc.),
never in this repo, never in git, never in the backup archive.

1. BACKUP_PASSPHRASE
   ---------------------------------------------------------------------------
   Encrypts every nightly archive (7-Zip, AES-256, encrypted headers).
   Currently set in .env on this machine (key: BACKUP_PASSPHRASE).
   Copy the value into a password manager now — see docs/BACKUP.md,
   section "The passphrase". Changing it later does not re-encrypt old
   archives; they stay on the old value.

2. pickixo_admin's PostgreSQL password
   ---------------------------------------------------------------------------
   Needed to restore the database on a new machine. pg_dumpall runs with
   --no-role-passwords on purpose, so globals.sql carries role NAMES but never
   passwords. pickixo_app deliberately has no CREATEDB, so only pickixo_admin
   can create the database during a restore, or run Test-Restore.ps1's deep
   -AdminUrl check. This password is not stored anywhere in this repo or in
   .env — it exists only wherever it was set when the role was created.
   Write it down.

3. Google account login for the Drive holding the backups
   ---------------------------------------------------------------------------
   Currently: monjurhye@gmail.com (see docs/BACKUP.md). Without this login
   (and its 2FA, if enabled), nobody can retrieve a single archive, however
   intact they are in Drive.

--------------------------------------------------------------------------------
Everything else needed for a restore already travels automatically inside the
nightly AES-256 archive, so it does not need separate safekeeping:

  - pickixo_app's password        (inside DATABASE_URL, inside secrets/.env)
  - the TLS certificate and key   (secrets/certs/)
  - nginx.conf                    (config/nginx.conf)
  - service definitions           (config/services.txt)
  - the full source tree          (source/, including uncommitted work)

See docs/BACKUP.md for the full restore procedure, and
scripts/backup/Test-Restore.ps1 to prove any of this actually works before you
need it for real.
